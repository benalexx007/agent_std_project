# research-write

Use existing brief/protocol/claim map and cite source locations. Outline may precede experiments; numerical results and conclusions must follow actual evidence. Generate tables/figures reproducibly from recorded outputs. Preserve limitations, negative findings and unresolved claims. Check numbers/citations/terminology and venue guidance only when a venue is selected. Distinguish draft readiness from publication acceptance.

Follow the research output profile: paper, proof, report or artifact. A report for development of the harness is separate from scientific outputs. Use export-research to retrieve the review/evidence packet, not as a finished or verified manuscript. Keep conjectures, proof sketches and numerical checks at their recorded evidence level. If a format compiler is unavailable, deliver editable source and report the unavailable build; never claim a successful build without evidence.

Choose task_class by the work: synthesis_planning for an independently verified project/argument plan, analysis for substantive drafting/revision, automation for a predefined production procedure. Writing a summary does not itself satisfy the planning verification contract.

Use the role, study guidance, acceptance criteria and effective configuration supplied with the task. Load only the artifacts needed for the current question. Return a concise result with evidence references, performed checks, limitations and unresolved items using the harness result contract when dispatched by the harness. Keep durable evidence outside chat.

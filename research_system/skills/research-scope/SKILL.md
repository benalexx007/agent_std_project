# research-scope

Create a brief with question, study type, existing assets, intended output, assumptions, resource bounds and an observable stopping condition. Separate scientific uncertainty from missing user preference. Reuse known constraints and ask only for decisions that affect the next action. A small question can be answered in the task record; do not create a full project scaffold.

Separate the knowledge goal (discovery, extension, reproduction or synthesis), reasoning needed, and paper/proof/report/artifact output. A report about building this harness does not change the output of a research project using it. Identify what is unknown and what would resolve it; do not turn a citation lookup into open-ended discovery.

When the task synthesizes a final plan, use synthesis_planning and independently verify/research primary evidence before committing. Pass prior analysis as labelled artifacts, retain assumptions and blocking questions, and provide planning_review. Ordinary clarification/analysis remains analysis; a scripted workflow need not call a model.

Use the role, study guidance, acceptance criteria and effective configuration supplied with the task. Load only the artifacts needed for the current question. Return a concise result with evidence references, performed checks, limitations and unresolved items using the harness result contract when dispatched by the harness. Keep durable evidence outside chat.

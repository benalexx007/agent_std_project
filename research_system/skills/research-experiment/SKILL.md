# research-experiment

Implement the smallest meaningful feasibility check, then the authorized protocol. Record code/patch, data/config/model/environment, raw outputs, failures and commands. Validate metric/splits or proof obligations before expensive work. Register jobs and cancellation limitations. Preserve outputs when interrupted, label incomplete/stale results, and rerun only affected dependencies. Do not start paid or live evaluation merely because the skill was selected.

Map assumptions/formulas/predictions to code and measurements. Use the relevant tool or verifier when available; save raw outputs and versions, and keep numerical/symbolic evidence distinct from a proof. Publish observations as evidence records, including failed_run when execution failed. Use a subject reference for the exact hypothesis/plan version observed, and a dependency reference for a conclusion that must be reviewed when its premises change.

Every benchmark execution requires a fresh human confirmation with its protocol document and bounded scope. A proposed benchmark, available quota or earlier approval is not permission to run it.

Implementation, interpreting results and debugging use analysis. Automation applies to executing an already defined procedure with few new decisions; run deterministic scripts directly when sufficient. If new evidence requires redesigning/finalizing the overall plan, return to synthesis_planning for independent verification rather than silently changing the protocol in an automation step.

For delegated work that may span attempts or workers, read [work-unit handoff](references/work-unit-handoff.md) before starting long tool operations.

Use the role, study guidance, acceptance criteria and effective configuration supplied with the task. Load only the artifacts needed for the current question. Return a concise result with evidence references, performed checks, limitations and unresolved items using the harness result contract when dispatched by the harness. Keep durable evidence outside chat.

For supported statistical helpers or scientific figures, read [analysis tools](references/analysis-tools.md). Use the provisioned interpreter for general project code inside the backend sandbox.
